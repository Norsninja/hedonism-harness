# v0.2 Reflex Cell Spec

Status: active
Supersedes: nothing (parallel branch to SPEC.md v0.1)
Date: 2026-05-04

## Purpose

Define the thesis-aligned primitive organism architecture as a parallel branch
to the v0.1 deliberative-cell substrate. The v0.1 substrate (HedonismPolicy
+ valence harness + voluntary REPRODUCE) is retained as a comparison model.
This spec defines the reflex-cell substrate that the project will use as the
primary organism architecture going forward.

## Thesis

Every behavior in a primitive organism reduces to response to pleasure and
pain stimuli. There is no deliberation, no future-state simulation, no
multi-component cognitive scoring. The cell senses gradients, moves along
the net pleasure-minus-pain field, eats reflexively when on food, divides
when internal state permits. Traits modulate sensitivity coefficients.
Selection acts on traits via inheritance plus mutation across generations.

## Cell behaviors (atomic primitives)

A reflex cell exhibits exactly six behaviors, all derived from pleasure/pain:

1. Sense pleasure gradient and pain gradient in the four cardinal directions
   (current sensors: food_signal_*, hazard_signal_*).
2. Move along the net positive gradient when one exists.
3. Eat automatically when on a cell with food (no decision; reflex).
4. Take damage automatically on hazard residency (current behavior).
5. Reproduce automatically when energy and age thresholds permit and a
   neighbor cell is open (no decision; substrate-triggered).
6. Pass traits to offspring with mutation; mutation may push trait values
   outside the founder distribution range (unbounded with physical floors).

## Architecture decisions

### Policy: GradientPolicy

Single-tick decision based on the agent's current observation only. No
predict-one-step. No call to evaluate(). No multi-component harness.

Decision rule:

```
if obs.on_food and obs.current_food_value > 0:
    return Action.EAT

pleasure_pull[d] = obs.food_signal_d * traits.pleasure_sensitivity * (1 + obs.hunger_level)
pain_pull[d]    = obs.hazard_signal_d * traits.fear_sensitivity * (1 - traits.risk_tolerance)
net[d]          = pleasure_pull[d] - pain_pull[d]
net[Action.STAY] = 0.0

return argmax(net) over valid actions
```

REPRODUCE is never selected by GradientPolicy. The action remains in the
Action enum and in get_valid_actions output for HedonismPolicy backward
compatibility.

Hunger amplification (1 + obs.hunger_level) implements substrate-aligned
internal-state sensitization: a hungry cell perceives food gradients more
strongly. This is the only place internal body state enters the policy.

Implementation target: under 60 lines including imports and docstring.

### Reproduction: automatic, substrate-triggered

Trigger lives in model.step() as a new tick phase between metabolism+memory_decay
(phase 4) and hazard residency (phase 5). Concretely:

```
4.  apply_metabolism + apply_memory_decay
4.5 apply_auto_reproduction      <- new
5.  apply_residency_damage
6.  death_sweep
7.  process_birth_queue
```

apply_auto_reproduction iterates living agents and queues a birth via the
existing _birth_queue when:

- agent.body.alive
- agent.body.energy >= reproduction_config.energy_threshold
- agent.body.age >= reproduction_config.min_age
- at least one neighbor cell is open at trigger time

If no open neighbor is available, no birth is queued this tick; trigger
re-evaluates next tick (no per-agent retry queue needed; the loop runs
every tick).

The existing _process_birth_queue / process_reproduction infrastructure is
reused unchanged. ReproductionRequested events are still emitted at the
trigger site so existing metrics aggregators continue to count requests.

### Memory: stripped from v0.14

GradientPolicy reads no memory fields. The Observation dataclass still
exposes remembered_* fields (zero-defaulted when memory=None). Memory
primitives (ValenceMemory, DirectionalMemory) remain in core/memory.py
and are still consumed by HedonismPolicy.

Memory is deferred, not abandoned. v0.15+ may reintroduce a directional
gradient reinforcement under GradientPolicy after v0.14 establishes
baseline reflex-cell dynamics.

### Traits: full inheritance, schema fixed, values emergent (A + C)

The existing Traits dataclass (11 fields) is inherited unchanged by
ReflexCell. Mutation infrastructure is unchanged. GradientPolicy reads
only:

- pleasure_sensitivity
- fear_sensitivity
- risk_tolerance
- sensor_radius (consumed by sensors.observe)

Internal state enters the policy via Observation.hunger_level, not via
trait fields directly.

Inert under GradientPolicy: novelty_drive, reproduction_drive,
memory_strength, memory_decay_rate, hunger_pain_sensitivity,
injury_pain_sensitivity, pain_tolerance. Inert fields still mutate
across generations and remain in the lineage record. They affect
HedonismPolicy and may become relevant if v0.15+ reintroduces memory.

Founders sample uniformly from TraitConfig ranges. **No archetype
injection in v0.14 founder pipeline.** experiments/trait_archetypes.py
remains in the repo as a comparison tool but is not invoked by
v0.14 sweeps.

Mutation is unbounded. Lineages may drift outside the initial TraitConfig
ranges. Physical floors enforced at the mutation site:

- sensitivity-class fields >= 0.0
- tolerance-class fields in [0.0, 1.0] (already bounded by semantics)
- sensor_radius >= 1
- decay/strength fields in [0.0, 1.0]

Floors do not box lineages; they prevent invalid values that would crash
the harness or the sensors.

Initial trait distribution width is wide. Specific TraitConfig range
values are defined in v0.14 pre-registration, not here.

### Speciation analysis (post-hoc, not core)

Per-lineage trait fingerprint logged at AgentBorn. Fields: lineage_id,
parent_id, birth_tick, full traits vector. Existing AgentBorn event
already carries lineage_id and tick; v0.14 extends the event payload
or writes a parallel CSV at run end.

Post-run analysis script (scripts/v0.14_speciation_analysis.py) reads
the trait fingerprint log and identifies clusters in trait space via
k-means or simple histogram analysis. Speciation is observation, not
ontology: clusters are post-hoc labels for empirical lineage groupings.

## Comparison framework (v0.14)

Three-arm comparison on food_ladder + tight_gradient, 8 seeds per arm
per chamber, 200 ticks, 5 founders. 3 arms x 2 chambers x 8 seeds = 48
runs.

| arm | policy | reproduction | label |
|---|---|---|---|
| A | HedonismPolicy | voluntary REPRODUCE action | deliberative-voluntary |
| B | HedonismPolicy | apply_auto_reproduction | deliberative-auto |
| C | GradientPolicy | apply_auto_reproduction | reflex-auto |

A is the v0.13b baseline (reproduces existing artifacts at the mem-off
cell when memory is disabled).
B isolates the reproduction-trigger effect (voluntary vs automatic).
C-vs-B isolates the policy-architecture effect (deliberative vs reflex).

Memory disabled across all 3 arms in v0.14: memory_type irrelevant
because both policies either don't read it (Gradient) or the
configuration sets memory=None (Hedonism with memory disabled).

Trait config: identical across arms. Wide ranges, no archetype
injection, unbounded mutation.

Pre-registered headline metrics:

- total_births
- seeds_with_any_births
- births_after_tick_50  (the H2 ceiling test from v0.13 Phase 1)
- max_population_end
- seeds_with_survivors at run end
- still_tick_fraction (action == STAY rate)
- decision_economy: policy module LOC (informational, not gating)

Pre-registered comparisons:

- C - A on births_after_tick_50: positive value tests the thesis claim
  that the reflex architecture supports lineage compounding the
  deliberative architecture does not.
- B - A on the same metric: isolates the reproduction-trigger effect.
- C - B on the same metric: isolates the policy-architecture effect.

The v0.7b 6-criterion qualification rule is dropped for v0.14. The rule
was designed for memory-grid sweeps where qualification gated winner
selection; the comparison framework uses headline-metric deltas instead.

## Falsification stance

The project does not pre-commit to a falsification criterion for the
thesis itself. Outcomes and project response:

- C produces births_after_tick_50 > A and B do not.
  -> Reflex architecture is sufficient for lineage compounding under
  the existing substrate. Thesis evidenced. Continue with v0.15
  (reintroduce minimal memory under GradientPolicy).

- All three arms hit the same tick-50 ceiling.
  -> Ceiling is substrate-physical (reproduction economics or chamber
  design), not policy-architectural. v0.15 targets substrate parameters
  (energy_cost, n_ticks, layout dimensions).

- C produces no births at all or a regression vs A and B.
  -> Engineering finding, not thesis falsification. Inspect
  GradientPolicy for missing pleasure-pain channel coverage. Worth
  considering: hunger-pain as an internal pull (not just external
  gradient), pain accumulation across ticks (memory-light), or trait
  range mismatch.

- C plateaus below A but produces nontrivial dynamics.
  -> Deliberative cognition provides value beyond raw gradient
  response. v0.15 investigates which harness component carries it
  (likely safety_pleasure or anticipated_food_pleasure).

The project continues regardless of outcome. The substrate (world,
body, traits, sensors, mutation) is the asset. Selection on
heritable traits is the engine. The policy is one swappable
component.

### Determinism contract

GradientPolicy must be a pure function of (Observation, Traits). No RNG
read except for tie-breaking when multiple directions share the maximum
net pull. Tie-break uses ctx.rng identically to existing policies.

apply_auto_reproduction must produce identical _birth_queue ordering as
voluntary REPRODUCE under matching (energy, age, neighbor) state.
Determinism test: with HedonismPolicy + apply_auto_reproduction (arm B)
on a frozen seed, the birth event sequence matches the voluntary-arm
event sequence at agent-state boundaries (births fire at the same
agents at the same ticks, modulo the action emission itself).
