# Local corpus manifest — v0.34..v0.39 reducers

**Status:** living doc. Last extended 2026-05-06 (through v0.39).
Supersedes [[docs/artifacts/v0.34_v0.38_local_corpus_manifest.md]] as
the active regen cookbook. The v0.38 manifest is preserved as a
sealed historical record (do NOT rewrite it).

`runs/` is gitignored. A clean clone has zero corpus on disk and must
regenerate before any reducer can run.

## What "the v0.34..v0.39 corpus" means

128 runs at the locked parameters used by every reducer in the
lineage arc:

- chamber: `tight_gradient`
- influx: `1.0`
- hazard ∈ {0, 4, 8, 12}
- 32 seeds per hazard (v0.25 1..8 + v0.32 9..16 + v0.33 17..24 +
  **v0.39 25..32**)
- N_TICKS = 200
- N_FOUNDERS = 5

Total: 4 hazards × 32 seeds = **128 runs**.

The OLD 96-run corpus (v0.25 + v0.32 + v0.33) is unchanged and
remains the v0.34..v0.38 reducers' input. The NEW 32-run fresh
stream (v0.39) is consumed by the v0.39 reducer and by two thin
v0.34 / v0.35 extension reducers that write to SEPARATE output dirs.

## Sweep regeneration commands (in order)

```
uv run python scripts/v0.25_sweep.py    # ~60s; seeds 1..8; both chambers
uv run python scripts/v0.32_sweep.py    # ~13s; seeds 9..16; tight_gradient only
uv run python scripts/v0.33_sweep.py    # ~13s; seeds 17..24; tight_gradient only
uv run python scripts/v0.39_sweep.py    # ~10s; seeds 25..32; tight_gradient only
```

Total wall time for sweeps: ~96s. v0.32 / v0.33 / v0.39 are
independent of each other and may be run in parallel.

Output trees:

- `runs/fear-hunger-v0.25-tight_gradient/` (used by v0.34..v0.38)
- `runs/fear-hunger-v0.25-food_ladder/` (NOT used by lineage reducers)
- `runs/fear-hunger-v0.32-tight_gradient/` (used by v0.34..v0.38)
- `runs/fear-hunger-v0.33-tight_gradient/` (used by v0.34..v0.38)
- `runs/fear-hunger-v0.39-tight_gradient/` (used by v0.39 only;
  NOT consumed by v0.34..v0.38 reducers — they would halt on
  B_POOL_ANCHORS drift if v0.39 runs were included)

## Reducer commands (in order; <5s each on the relevant corpus subset)

```
# OLD-corpus reducers (96 runs; v0.34..v0.38 in production)
uv run python scripts/lineage_replay.py            # v0.34 -> runs/lineage-v0.34/
uv run python scripts/lineage_survival_replay.py   # v0.35 -> runs/lineage-v0.35/
uv run python scripts/trait_replay.py              # v0.36 -> runs/lineage-v0.36/
uv run python scripts/lock_in_timing_replay.py     # v0.37 -> runs/lineage-v0.37/
uv run python scripts/leader_advantage_replay.py   # v0.38 -> runs/lineage-v0.38/

# FRESH-stream extension reducers (32 runs; v0.39 prerequisites)
uv run python scripts/lineage_replay_v0_39_extension.py
                                # v0.34 over fresh -> runs/lineage-v0.34-fresh/
uv run python scripts/lineage_survival_replay_v0_39_extension.py
                                # v0.35 over fresh -> runs/lineage-v0.35-fresh/

# v0.39 reducer (consumes BOTH old-sealed + fresh-extension outputs)
uv run python scripts/v0_39_leader_advantage_fresh_replay.py
                                                   # v0.39 -> runs/lineage-v0.39/
```

Strict ordering required by the re-anchor stack:

- Each OLD-corpus reducer reads earlier OLD-corpus outputs (see
  v0.34_v0.38 manifest for full graph).
- v0.34 fresh extension is independent of v0.35 fresh extension (only
  needs the v0.39 sweep output).
- v0.35 fresh extension reads v0.34 fresh extension output (anchors
  against `runs/lineage-v0.34-fresh/run_summary.csv`, NOT the sealed
  96-row output).
- v0.39 reducer reads BOTH:
  - sealed `runs/lineage-v0.34/run_summary.csv` (96 rows; halt if
    missing or row-count drifted)
  - sealed `runs/lineage-v0.35/pre_post_dominance.csv` (96 rows)
  - sealed `runs/lineage-v0.38/per_run.csv` (96 rows; for pooled
    aggregation of leader_advantage)
  - fresh `runs/lineage-v0.34-fresh/run_summary.csv` (32 rows)
  - fresh `runs/lineage-v0.35-fresh/pre_post_dominance.csv` (32 rows)

If any prior reducer's output is missing, the dependent reducer
halts with a `LineageReplayError`.

## Operational notes

- All reducer outputs are pure functions of the on-disk sidecars +
  per-arm `comparison.csv`. Re-running a reducer over the same
  corpus is idempotent.
- A failed re-anchor is **always** the right behaviour. If
  `LineageReplayError` fires on a re-anchor, the corpus has drifted
  (different seed, different sweep, different chamber) and the
  reducer's output cannot be trusted. Investigate; do NOT bypass
  the halt.
- Wall-time budget for full regen + all reducers: ~96s sweeps + ~17s
  reducers ≈ **115s** end-to-end.

## Strategic state at v0.39 handoff

The v0.34..v0.38 lineage-axis arc is flagged as
**single-stream-correlational**. v0.39's fresh-stream calibration
(seeds 25..32) failed to reproduce v0.38's H5 LEADER-ADVANTAGE-
AMPLIFIED finding, and descriptively the v0.34 (`top_lineage_b50_share`)
and v0.35 (`wad_rate`) hazard-amplification patterns also do not
reproduce on the fresh stream. v0.36 (founder-trait) and v0.37
(stabler-early-leadership) were not tested on the fresh stream and
remain unaffected by v0.39.

v0.40+ candidates: second fresh stream (33..40), per-stream variance
decomposition, mortality/windowed-b50/descendant-drift deferred
until the cross-stream calibration question is resolved. See
[[docs/experiments/fear_hunger_v0.39.md]] Conclusion for the full
deferred list.
