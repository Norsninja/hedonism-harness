## What "the v0.34..v0.40 corpus" means

128 runs at the locked parameters (unchanged from v0.34_v0.39):

- chamber: `tight_gradient`
- influx: `1.0`
- hazard ∈ {0, 4, 8, 12}
- 32 seeds per hazard (v0.25 1..8 + v0.32 9..16 + v0.33 17..24 +
  v0.39 25..32)
- N_TICKS = 200
- N_FOUNDERS = 5

Total: 4 hazards × 32 seeds = **128 runs**. v0.40's audit reads the
sealed v0.34/v0.35/v0.38 OLD reducer outputs (96 rows each) plus the
v0.34-fresh / v0.35-fresh / v0.39 FRESH reducer outputs (32 rows
each), and produces a new derived audit layer at
`runs/lineage-v0.40/`.

## Sweep regeneration commands (in order; unchanged from v0.34_v0.39)

```
uv run python scripts/v0.25_sweep.py    # ~60s; seeds 1..8; both chambers
uv run python scripts/v0.32_sweep.py    # ~13s; seeds 9..16; tight_gradient only
uv run python scripts/v0.33_sweep.py    # ~13s; seeds 17..24; tight_gradient only

```

Total wall time for sweeps: ~96s. v0.32 / v0.33 / v0.39 are
independent of each other and may be run in parallel.

## Reducer commands (in order; v0.40 last)

```
# OLD-corpus reducers (96 runs; v0.34..v0.38 in production)
uv run python scripts/lineage_replay.py            # v0.34 -> runs/lineage-v0.34/
uv run python scripts/lineage_survival_replay.py   # v0.35 -> runs/lineage-v0.35/
uv run python scripts/trait_replay.py              # v0.36 -> runs/lineage-v0.36/
uv run python scripts/lock_in_timing_replay.py     # v0.37 -> runs/lineage-v0.37/
uv run python scripts/leader_advantage_replay.py   # v0.38 -> runs/lineage-v0.38/

# FRESH-stream extension reducers (32 runs; v0.39 prerequisites)
uv run python scripts/lineage_replay_v0_39_extension.py
                                # v0.34 over fresh -> runs/lineage-v0.34-fresh/
uv run python scripts/lineage_survival_replay_v0_39_extension.py
                                # v0.35 over fresh -> runs/lineage-v0.35-fresh/

# v0.39 reducer (consumes BOTH old-sealed + fresh-extension outputs)
uv run python scripts/v0_39_leader_advantage_fresh_replay.py
                                                   # v0.39 -> runs/lineage-v0.39/

# v0.40 cross-stream stability audit (consumes 6 sealed CSVs; no raw
# events.jsonl parsing; no helper-function reuse)
uv run python scripts/v0_40_stream_stability_audit.py
                                                   # v0.40 -> runs/lineage-v0.40/
```

Strict ordering required by the audit's input dependencies:

- v0.40 reads the sealed outputs of v0.34, v0.35, v0.38, v0.39
  AND the v0.34/v0.35 fresh extensions. All seven of those
  reducers must complete first.
- v0.40 itself is independent of v0.36 (trait_replay) and v0.37
  (lock_in_timing_replay) — does not read those outputs.

If any prior reducer's output is missing, v0.40 halts via
`LineageReplayError` ("sealed CSV missing at ...").

## Operational notes

- All reducer outputs are pure functions of the on-disk sidecars +
  per-arm `comparison.csv`. Re-running any reducer over the same
  corpus is idempotent.
- v0.40 is **idempotent** because it reads sealed CSVs only. Re-
  running v0.40 produces byte-identical outputs.
- A failed re-anchor or invariant is **always** the right behaviour.
  Investigate; do NOT bypass the halt.
- Wall-time budget for full regen + all reducers including v0.40:
  ~96s sweeps + ~17s OLD/FRESH reducers + ~2s v0.40 audit ≈ **115s**
  end-to-end.
