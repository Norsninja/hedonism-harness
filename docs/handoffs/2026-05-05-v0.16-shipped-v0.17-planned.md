## Decisions locked in

- **Memory budget is scale-graded.** Cell tier = scalar (1 float + last move). Multi-cell tier = directional EMA (deferred). Organism tier = spatial map (much further deferred). v0.15 doc §"Memory budget — scale-graded".
- **Hunger gate is a hard sated veto** (not multiplicative). v0.15 §"Hunger gate".
- **`unbounded_mutation` default stays `False`** — v0.7..v0.13 bit-identity is load-bearing.
- **v0.16 instrumentation change is intentional.** AgentBorn/AgentDied no longer count as "other action ticks"; cleaner dispatch enables per-parent telemetry. Shifts `still_tick_fraction` ~1.4 pp vs v0.14/v0.15 published numbers; simulation unchanged. v0.16 §"Determinism note".
- **v0.17 design (agreed in conversation; not yet committed):**
  1. **Single-axis sweep, not serial.** Drop the v0.16 doc's "tight_gradient geometry as v0.17 step 2" plan. Single sweep on `offspring_start_energy ∈ {30, 60, 100}` on both chambers under reflex-baseline + cost-15. 48 runs.
  2. **Wider band {30, 60, 100}** (not {30, 50, 70}) — spans 3.3x for clear plateau test.
  3. **Add `total_grandchildren_count`** to RunDiagnostics: count births where parent_id ∈ children_ids (i.e. parent was itself born during the run). Direct compounding metric — `births_after_tick_50` is a tick-window proxy. ~10 LOC.
  4. **Honest conservation caveat in pre-reg.** Raising `offspring_start_energy` is a free energy handout (no conservation). Even if it lifts compounding, the result is "substrate compounds when given a handout." v0.18 = food respawn / regrowth under conservation, regardless of v0.17 outcome.
  5. **Defer tight_gradient geometry** to v0.18+ if v0.17 doesn't resolve the tight_gradient hard zero.

## Watch-outs

- **`food_events` identical across every arm in v0.15 and v0.16** (192 / 174). The chamber's food supply is hard-capped. Even infinite child energy may not lift compounding if children compete for the same fixed pool. v0.17 result will tell us; if it doesn't lift, food respawn (v0.18) is the next axis.
- **`offspring_start_energy` is a free handout** — no conservation. Document this in the v0.17 pre-reg and frame results accordingly.
- **The remote `claude/v0.X-*` branches all linger.** Sandbox blocks `git push --delete`. Local prune is sufficient; same pattern from v0.9 onward.
- **`tuned_reproduction_config` validates `[0.0, 100.0]`** on each numeric axis. `offspring_start_energy=100` is at the ceiling. Pre-reg should pin a value below the ceiling (e.g. 100, not 100.0001). If we want to test 150, raise the bound first — but probably unnecessary.
- **Determinism contract**: arm with `offspring_start_energy=30` (the v0.14/v0.15/v0.16 default) must reproduce v0.16 cost-15 bit-identically on `(total_births, births_after_tick_50, seeds_with_survivors, food_events)`.
- **`max_event_tick` heuristic** in `_read_run_diagnostics`: parents alive at run end use the last event's tick as their lifespan endpoint. Run end is typically `n_ticks - 1`. If a future driver writes a final "summary" event at a higher tick, that would skew the metric. Currently no such event exists.
- **v0.16 PR description claimed `(total_births, births_after_tick_50, survivors, food_events)` bit-identity** for cost-35 vs v0.15 reflex-baseline. Verified at sweep time; will need to re-verify in v0.17 sweep that `offspring_start_energy=30` reproduces v0.16 cost-15 on the same triple.
