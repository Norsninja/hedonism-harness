## Decisions locked in

- **Six-flow conservation bookkeeping (a/a heat-loss).** Initial chamber paint free; respawn + child startup debit pool; parent reproduction cost + metabolism = heat loss (destroyed); death residual credits pool; ambient influx credits open-ecology pool. See pre-reg §"Conservation framing".
- **Empty-pool denial is atomic.** Birth denied; parent retains `energy_cost`; re-eligible next tick. New telemetry `pool_birth_denied` (`PoolBirthDenied` events). Mirrors the existing `find_adjacent_empty_cell` rejection contract.
- **Respawn failure clears the schedule** (option (i), pre-committed). Cell stays EMPTY, `respawn_at_tick` reset to 0, `PoolRespawnDenied` emitted. No deferred-refill mechanic.
- **Influx is deterministic constant** per phase 0; no new RNG stream. `energy_pool_initial=None` + `ambient_influx_rate=0.0` preserve v0.7..v0.18 bit-identity by construction.
- **Death residual = `max(0.0, body.energy)`** at AgentDied, credited synchronously in `record_death` (no signal handler — `record_death` already has the agent reference).
- **v0.19 brackets corrected mid-session.** Original {5K, 15K, 30K} were 8× too generous (per-arm aggregate flows treated as per-run); rescaled to {500, 1500, 3000} after first sweep. Demand-math correction documented in pre-reg.
- **H10 falsified within {500, 1500, 3000}.** Closed-3000 = inf-pool exactly; no over-pool regression in this range. Productive sweet spot is at-or-above demand, not strictly between two failure modes. v0.18 K-20 over-saturation phenomenon does not have a parallel here.
- **Three v0.18 findings refined** (per pre-reg §"Three v0.18 findings now resolve / refine"): renewable-food finding holds under strict conservation; pool exhaustion is gradient not cliff; death residual is chamber-asymmetric (zero on tight_gradient, ~80/seed on food_ladder).
- **v0.20 candidate is (c) parent-funds-child.** Parent transfers `energy_cost` directly to child instead of pool funding `offspring_start_energy`. Child startup is 30-35% of total pool drain, so (c) measurably shifts demand. Closed-1500 partial-conservation arm is the cleanest test case.

## Watch-outs

- **Per-run vs per-arm aggregate flows.** v0.19's first-sweep error multiplied 8 seeds' worth of flows by 8 again. When estimating pool demand or influx rates, divide v0.18-style aggregate metrics by `n_seeds` first. Pre-reg has the corrected math anchored on empirical telemetry.
- **`food_consumed_per_birth` under blocked arms is misleading.** Denominator effect: blocked births depress denominator while food consumption continues. fcpb should always be reported alongside block counts; or use `food_consumed / (births + pool_birth_denied)` for a corrected ratio.
- **Death residual is chamber-asymmetric.** tight_gradient's in_death = 0 because every death is starvation (energy ≤ 0). food_ladder gives ~80/seed from hazard injuries. Conservation recycling is a chamber feature, not a substrate feature. v0.20 sweeps that vary chamber geometry need to track this.
- **Bit-identity transitive chain.** v0.19 inf-pool reproduces v0.18 K-50 reproduces v0.17 start-30 reproduces v0.16 cost-15 — anchoring back to v0.7-era determinism. v0.20 must continue this: `parent_funds_child=False` (the new field default) preserves v0.19 bit-identity.
- **`record_death` does the pool credit directly** (not via signal handler). The pre-reg said "subscribe AgentDied" but the implementation is synchronous in `record_death` because `AgentDied` doesn't carry `body.energy`. Same semantic; simpler wiring. v0.20 doesn't need to revisit this.
- **Placement pre-check before pool debit.** `_process_birth_queue` calls `find_adjacent_empty_cell` first when a pool is configured; this avoids needing a refund channel. v0.20 (c) modification should preserve the pre-check (and skip the pool-debit step entirely).
- **Empty-pool fail-soft on respawn (option (i)) clears the schedule.** Cell becomes permanently lost until eaten again. Under v0.20 if the pool path changes shape, preserve this — option (ii) deferred-refill was rejected for closed-pool clarity.
- **Mesa PropertyLayer dtype matching.** Existing layers use precise `default_value=np.{dtype}(...)`. v0.19 added no new layers (pool is a scalar on the model). v0.20 likely doesn't either, but if a per-tile field is added, match dtype precisely or Mesa warns.
- **Sandbox cannot `git push --delete`.** Local prune is sufficient. The user has been pruning merged remote branches between sessions.
- **`scripts/v0.14_speciation_analysis.py` is hardwired to v0.14 paths.** Speciation snapshot for v0.17/v0.18/v0.19 lineages remains deferred. The `runs/fear-hunger-v0.19-*/` directories preserve the data on disk (not committed; gitignored).
- **`pool_out_child_startup` is 30-35% of total drain.** That's the load-bearing number for v0.20 design rationale; if v0.20 (c) doesn't measurably shift the partial-conservation regime, the candidate hypothesis is falsified rather than the substrate.
