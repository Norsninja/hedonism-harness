## Decisions locked in

- **Conservation framing pivot.** v0.18 PROVES the substrate compounds under non-saturating food at offspring=30 (no handout). It does NOT yet prove compounding under strict conservation. Wording: "renewable / non-saturating food" or "environmental food accounting is plausible," not "compounds under conservation."
- **food_consumed_per_birth is the conservation-accounting metric.** Floor = `energy_cost + offspring_start_energy = 45`. v0.17 start-100 was 9.5 (gap = handout); v0.18 productive arms 51-95 (above floor).
- **K=0 rejected at config validation.** Pydantic `ge=1` on `food_respawn_cooldown`; sentinel 0 = unscheduled, K=0 would clash on tick 0.
- **Respawn refills regardless of occupancy.** Pre-committed in v0.18 pre-reg; avoids stationary-agent-blocks-respawn fairness asymmetry.
- **No new RNG stream for v0.18 respawn.** Cooldown is fully scheduled (per-tile, no rolls); `K=None` preserves bit-identity by construction.
- **v0.19 = strict mass-energy conservation, two-tier.** (A) Closed pool: no external influx, death recycles. (B) Open ecology: small ambient influx, death recycles. Run both; closed pool may decay/stagnate, open ecology may be more biologically realistic.
- **v0.18b combined-axis (respawn + offspring=100) deferred indefinitely.** v0.18 K-20 on food_ladder reaches 83% of v0.17 start-100 b>50; remaining ~17% gap is small enough that v0.19 strict-conservation should subsume the question.
- **K-20 over-saturation regression on tight_gradient is a real substrate finding.** 130→43 b>50 despite more food. Non-monotonic food-density / compounding relationship; pre-reg-cite for v0.19 expectation that productive K (or pool size) exists between under- and over-saturation.

## Watch-outs

- **`food_consumed_per_birth` floor is `energy_cost + offspring_start_energy`** (currently 45). If v0.19 changes either, recompute floor for interpretation.
- **The K-20 over-saturation regression on tight_gradient** is a real finding. v0.19 sweeps should bracket the productive regime; expect non-monotonicity in pool-size or influx-rate too.
- **Respawn under occupant fires unconditionally.** Test `test_respawn_under_occupant_keeps_cell_food` pins this. v0.19 must preserve symmetry (don't add an "occupied → skip" branch).
- **Sender-scoped signal handlers.** `signal_for(AteFood).connect(handler, sender=self)` — the handler closure captures `self` and is stored on the instance to defeat blinker's weak-references. v0.19 `AgentDied` handler must follow the same pattern.
- **`respawn_at_tick=0` is the unscheduled sentinel.** Any v0.19 code touching this layer must preserve the 0-means-unscheduled invariant.
- **Bit-identity transitive chain.** v0.18 K-inf reproduces v0.17 start-30 reproduces v0.16 cost-15, all the way back to v0.7-era determinism on shared seeds. v0.19 must continue this — config field default that disables the new mechanism preserves the chain.
- **Mesa PropertyLayer dtype matching.** Existing layers use `default_value=np.{dtype}(value)` matched with `dtype=np.{dtype}`. The respawn layer is int32; v0.19 pool/influx fields likely float32. Match precisely or Mesa warns.
- **`scripts/v0.14_speciation_analysis.py` is hardwired** to v0.14 paths. Speciation snapshot for v0.17/v0.18 lineages was deferred (the `runs/fear-hunger-v0.17*/` and `runs/fear-hunger-v0.18*/` directories preserve the data). Optional follow-up at any time.
- **Sandbox cannot `git push --delete`.** Local prune is sufficient.
- **Remote `claude/v0.X-*` branches all linger** including v0.18-food-respawn (just merged). Same pattern from v0.9 onward.
